# 작은 화면과 실제 자료 탐구 과정 검토

## 수정 범위

- 첫 화면의 `max-height: 700px` 규칙이 가로 배치를 세로로 바꾸는 반면, 상위 영역은 스크롤을 막아 시작 버튼이 화면 밖에 갇혔다. 첫 화면의 높이 소유권과 좌우 배치를 별도로 명시했다.
- 이해 과정은 고정된 2×2 흑백 그림의 정답 맞히기에서, 현재 수집한 자료를 사용하는 네 장면으로 교체했다. 각 장면은 자유롭게 왕복한다.
- 자료를 숫자로 → 분포 비교 → 뉴런의 곱할 수와 더할 수 조절 → 뉴런 출력을 연결하여 최종 경계 비교.
- 연습의 직접 고치기 버튼은 별도의 과제를 열지 않고 같은 이해 과정으로 돌아온다. 기존 자동 학습 상태와 탐구용 모델 상태는 서로 보존한다.

## 개념과 계산의 경계

- 승부차기는 키커와 골키퍼의 좌우를 숫자로 기록한다. 사진의 높이나 명암을 입력으로 설명하지 않는다. 가운데 방향은 이 단순 규칙의 판정 대상에서 제외한다.
- 이미지의 실제 픽셀, 특징별 곱셈표, 가중합, 평균·축척을 이용한 좌표를 연습 저장소와 공유한다. 새 특징도 기존 편집기를 이용해 추가한다. 클래스 이름은 특징 계산에 사용하지 않는다.
- 뉴런 자체가 선인 것은 아니다. 이 실험의 은닉 뉴런은 두 입력에 각각 수를 곱하고 더한 뒤, 음수를 0으로 바꾸는 계산기다. 색 선은 그 합이 0인 자리다. 한 뉴런 보기의 배경색은 클래스가 아니라 양의 뉴런 출력의 크기를 표시한다.
- 출력의 수는 클래스 수다. 출력은 은닉 뉴런의 값에 각각 연결값을 곱하여 더한다. 여기 표시하는 값은 확률이 아닌 점수다. 검은 경계는 가장 큰 점수의 클래스가 바뀌는 자리다.
- 새 뉴런은 출력 연결을 0으로 두어 추가만으로 기존 예상이 바뀌지 않는다. 연결한 후 서로 다른 뉴런의 0 기준을 넘나들면 최종 경계가 꺾일 수 있다.
- 슬라이더 조작은 원리 탐구이며 자동 최적화가 아니다. 자동 1번 고치기는 모든 실제 자료에 기존 역전파 코드를 적용한다. 정답률이 매번 올라간다고 약속하지 않는다.
- 이해의 두 입력 ReLU 모델은 별도 실험이다. 전체 그림 학습 모델과 동일하다고 주장하지 않는다. 연습에서는 중간값을 바꾸는 방법도 선택할 수 있다.
- 계산은 반올림 전 값으로 수행하고 화면은 소수 둘째 자리로 표시한다.

## 확인

- 브라우저 1397×655: 다섯 문제의 시작 버튼이 모두 화면 안에 있고, 첫 화면 세로 스크롤 없음.
- 1552×728: 같은 좌우 구성과 접근 가능한 시작 버튼.
- 1024×768 / 768×1024: 이해 과정의 그래프·연결 지도·조작부·다음 버튼이 화면 안에 배치됨. 세로 태블릿의 문제 카드는 가로 넘김.
- 1397×655: 승부차기 네 이해 장면의 기본 조작부에서 내부 넘침 없음. OMR의 특징 변경, 한 칸씩 계산, 해당 픽셀 강조, 다음 단계, 실제 10회 학습을 브라우저로 실행.
- OMR에서 이해 중 선택한 `lr` 특징이 연습의 가로축 선택에도 유지됨. 직접 탐구 버튼으로 3번째 장면에 복귀하고 연결 지도가 표시됨.
- 단위/통합 테스트: 실제 픽셀→가중합→좌표 일치, 클래스 이름과 무관한 특징, 슬라이더 실제 모델 수정, 추가 뉴런의 초기 무영향, 실제 역전파, 되돌리기, 애니메이션 취소, 자유로운 장면 이동 및 기존 수집/내보내기 회귀 확인.

극도로 낮은 화면(높이 520px 이하)과 휴대폰 폭에서는 접근 불가능한 화면을 만드는 대신 스크롤을 허용한다. 상세 계산 설명을 펼쳤거나 클래스/뉴런이 많아지는 경우 조작부 내부에서 스크롤할 수 있지만 다음 버튼은 고정한다.
