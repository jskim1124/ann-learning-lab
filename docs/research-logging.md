# 연구용 raw 행동 로그 — 개발판

2026-10-02. **앱 배포와 별개로 실제 수집은 OFF. Google 로그인·지정 시트 연결·Apps Script 배포는 아직 수행하지 않음.**

## Google 스프레드시트 연결 — 연구자용 순서

현재 설정은 OFF이며 아래 절차를 **직접 적용할 때만** 실수집이 시작된다. 앱의 프로덕션 배포와 Apps Script 수신기 배포는 별개다.

1. 지정한 시트에서 **확장 프로그램 → Apps Script**를 연다. 기존 코드가 있다면 먼저 보관하고, 전용 스크립트 프로젝트에 [Code.gs](../integrations/google-apps-script/Code.gs) **전체**를 붙여 넣는다.
2. Apps Script **프로젝트 설정 → 스크립트 속성**에 아래 세 값을 저장한다.

   | 속성 | 값 |
   | --- | --- |
   | SHEET_ID | `1EO9SCthQHKgpCgiSVm8C571-LJwDqC-GE3JzSZxCrlU` |
   | STUDY_ID | `neural-lab-pilot` (서버의 RESEARCH_STUDY_ID와 동일) |
   | GATEWAY_SECRET | 별도 생성한 32자 이상 난수 비밀키 (서버와 동일) |

3. 함수 목록에서 **setupResearchSheets**를 선택해 한 번 실행하고 본인의 시트 접근 권한을 승인한다. `Participants`, `RawEvents`, `SurveyResponses` 탭과 헤더만 만든다. 기본 Sheet1은 그대로 둔다. 기존 탭 헤더가 다르면 덮어쓰지 않고 중단한다. `doPost`는 서버 요청용이므로 편집기의 실행 버튼으로 시험하지 않는다.
4. **배포 → 새 배포 → 웹 앱**: 실행 사용자는 **나**, 액세스는 서버의 로그인 없는 요청을 받을 수 있는 **모든 사용자**로 설정한다. 엔드포인트 주소는 공개될 수 있지만 서버 HMAC 서명이 맞는 요청만 기록한다. **스프레드시트 자체의 링크 공유는 비공개로 유지한다.** 학교 계정 정책에서 해당 액세스를 금지하면 우회하지 말고 관리자 승인 또는 다른 수신 서버를 사용한다.
5. 배포 후 `https://script.google.com/macros/s/…/exec` URL을 복사한다. 편집자 전용 `/dev` 주소는 쓰지 않는다. 코드 수정 후에는 **배포 관리 → 수정 → 새 버전**을 선택해야 기존 `/exec`에 반영된다.
6. 앱 서버의 `.env.local`에 아래 설정을 입력한다. 실제 비밀키는 채팅·Git·브라우저 코드에 넣지 않는다. 모든 키는 서로 다른 난수로 만들고, 가명 키는 다음 실행에도 유지한다.

   ```dotenv
   RESEARCH_MODE=google
   RESEARCH_ORIGIN=http://127.0.0.1:4174
   RESEARCH_STUDY_ID=neural-lab-pilot
   GOOGLE_CLIENT_ID=웹_애플리케이션_OAuth_클라이언트_ID
   RESEARCH_SHEETS_GATEWAY_URL=https://script.google.com/macros/s/배포_ID/exec
   RESEARCH_SHEETS_GATEWAY_SECRET=위_Gateway_Secret과_같은_값
   RESEARCH_SESSION_KEY=별도_32자이상_난수
   RESEARCH_PSEUDONYM_KEY=별도_32자이상_고정_난수
   RESEARCH_IDENTITY_KEY=별도_32바이트_난수를_base64로_인코딩한_값
   RESEARCH_ENROLLMENT_CODE=연구참여용_32자이상_별도_코드
   RESEARCH_CONSENT_VERSION=연구자가_확정한_안내문_버전
   RESEARCH_PROFILE_APPROVED=true
   ```

   마지막 두 설정은 실제 연구 안내·참여 절차를 검토한 뒤에만 설정한다. 현재 `.env.example`은 안전하게 OFF로 남겨 둔다. `RESEARCH_INSTRUMENT_JSON`을 비우면 제공받은 17문항·6점 척도를 사용한다. `VITE_` 접두사를 붙이면 비밀키가 클라이언트로 노출될 수 있으므로 사용하지 않는다.

7. Google Cloud에서 **웹 애플리케이션용 OAuth 클라이언트**를 만들고 승인된 JavaScript 원본에 `http://127.0.0.1:4174`를 등록한다. 로그인은 Google Identity Services의 ID 토큰을 서버에서 검증한다. 학생의 Google Drive/Sheets 접근 권한은 요청하지 않는다. 테스트 모드 계정·학교 계정 제한은 OAuth 설정에 맞춰야 한다.
8. Vite 개발 서버를 재시작한다 (`pnpm dev --host 127.0.0.1 --port 4174 --strictPort`). `vite preview`는 API 서버가 아니므로 실수집 확인용으로 쓰지 않는다.
9. 연구자 테스트 계정으로 로그인 → 기본정보·참여 확인 → 슬라이더 한 번 변경 → 검사 제출을 확인한다. 각 탭에 원응답/이벤트가 저장되는지 확인하고 같은 계정 재로그인 시 가명 ID가 유지되는지 검증한다. 테스트 응답은 실제 연구 데이터와 구분한다.

Apps Script는 동시 요청을 잠금으로 직렬 처리하며 실패한 저장은 확인 응답을 주지 않는다. 브라우저의 영속 대기함이 같은 이벤트 ID로 재시도한다. **30명 동시 접속 무손실 보장은 아직 하지 않는다.** Google 실제 계정/네트워크/누적 행 수에 따른 부하 검증이 필요하며, 장기간 고빈도 로그는 DB 수집 후 시트로 전달하는 구조가 더 적합하다.

공식 참고: [웹 앱 배포](https://developers.google.com/apps-script/guides/web), [스크립트 속성](https://developers.google.com/apps-script/guides/properties), [Google 로그인 클라이언트 설정](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid).

## 이번 구현 범위

- Google Identity Services 로그인 UI + 공식 `google-auth-library` 서버 검증.
- 첫 참여 때 연구 기본 정보와 참여 확인. 사용자가 제공한 **A1–A4, B1–B8** 12문항을 사용한다. 참여 안내문과 기관 절차는 연구자가 별도로 확정해야 한다.
- 동의 완료 전에는 행동 수집 없음. 수집 ON/OFF 상태를 표시한다.
- 연구별 가명 코드, 최소 계정 식별자의 인증 암호화, 서버 전용 시트 전송.
- 페이지·요소별 클릭, 포인터 시작/이동/종료, 슬라이더 입력 변경을 raw 로그로 수집하고 실제 사용자 명령·모델 상태 기록과 함께 저장한다. 자동 피드백·점수 해석·학습자 분류는 구현하지 않음.
- 첫 화면의 여섯 번째 **티처블 머신** 카드: 다른 문제와 같은 카드·상단 바를 사용한다. 클래스 생성/이름 변경/삭제, 선택 클래스 바로 아래 그림·웹캠·이미지 업로드, 연속 촬영, 자료 전체 보기/삭제, 학습/중지, 새 이미지·그림·웹캠 예측, 정답을 지정한 새 자료 검사, 모델 내보내기. 학습 설정은 자동이며 학생용 조절기를 두지 않는다. 학습 버튼을 누르면 자료 분포 → 실제 은닉 뉴런 반응 → 예상 결과를 보여 준다. 별도 이해 단계는 없다. 화면에서 비교 연구를 암시하는 안내는 제거했고 로그의 `condition=comparison`은 유지한다. 내부 시각화가 추가된 버전은 `tm-live-flow-v2`으로 구분한다.
- 우측 상단 **검사**: Likert 원응답, 문항별 이전/다음, 미응답 검증, 제출 식별자로 재전송 중복 방지. 자동 채점 없음.

## 로컬 실행

의존성 설치 후 일반 `pnpm dev --host 127.0.0.1 --port 4173`는 수집이 꺼져 있다.

가상 계정·메모리 수신기를 사용하려면 PowerShell에서:

```powershell
$env:RESEARCH_MODE = 'local'
$env:RESEARCH_ORIGIN = 'http://127.0.0.1:4174'
pnpm dev --host 127.0.0.1 --port 4174 --strictPort
```

`개발용 로그인 → 개발용 계정으로 확인 → 임시 정보·참여 확인` 후에만 이벤트를 수집한다. 실제 설정에서는 버튼이 `Google 로그인`으로 바뀐다. 이 모드는 실계정이나 Google 네트워크를 사용하지 않으며 **서버 재시작 시 받은 기록이 사라진다. 실제 연구에 쓰면 안 된다.** production/VERCEL 환경 및 외부 호스트에서는 local 모드를 거부한다. `vite preview`는 정적 UI 확인용이며 연구 API 서버가 아니다.

## 데이터 흐름과 저장 구분

```text
Google 로그인 → 서버 토큰 검증 → HttpOnly 세션
                            → 첫 참여 정보·참여 확인
학생의 명시적 조작 → 허용된 이벤트 → IndexedDB 대기함
                  → 동일 출처 API → 서명된 Apps Script 수신기 → Google Sheets
```

**행을 생성하는 기준은 이벤트·값 변경이며 시간 간격이 아니다.** 기존 30초 heartbeat 생성은 제거했다. 조작 없이 2분을 기다려도 추가 행이나 빈 전송 요청이 발생하지 않는 테스트가 있다. 세션 시작/명시적 로그아웃, 화면 가시성 변경도 실제 발생한 이벤트다. 애니메이션의 렌더 프레임이나 시계가 흐르는 것만으로 행을 만들지 않는다. 과거 자료를 읽기 위한 `heartbeat` 스키마 항목만 남아 있다.

기기 대기함은 가명 코드+연구 ID별로 분리한다. 재로그인해도 다른 계정의 대기 기록을 전송하지 않는다. 이벤트 UUID를 재사용해 재시도하며, **서버가 실제 기록 후 확인한 ID만** 대기함에서 제거한다. 전송만 5~7초 간격으로 묶는다(기기별 분산). 최대 200건/110,000바이트이며, 성공한 뒤 남은 기록은 1~1.5초 간격으로 이어서 전송한다. 오류 시 무작위 지연을 더한 지수형 재시도(최대 60초), 온라인 전환·창 숨김 때 재시도한다. 각 행에는 전송 시각과 별도로 원래 발생 시각·순번이 남는다. 많은 조작 또는 네트워크 장애 시 지연될 수 있으므로 ‘즉시 도착’을 보장하지 않는다.

기기 저장 실패·5만 건 한도 시 수집을 중지하고 경고한다. 브라우저 강제 종료 순간의 미완료 쓰기, 사이트 데이터 삭제, 저장 공간 제한까지 무손실이라고 주장할 수 없다. **로그아웃 시 미전송 기록을 삭제하지 않는다.** 새 수집을 중지하고 진행 중인 전송 확인을 기다린 뒤 종료하며, 남은 행은 같은 연구·가명 계정으로 같은 기기에서 다시 로그인해야 전송한다. 공유 기기에 남는 수치 자료의 보관·삭제 절차를 연구 안내에 명시해야 한다. 다른 계정에서 조회·전송하는 기능은 없지만 기기 관리자에 대한 암호화 저장소는 아니다. 전송 완료 연구 자료 삭제도 자동 수행하지 않는다.

### 시트 탭

| 탭 | 내용 |
| --- | --- |
| `Participants` | 가명 코드, 참여 안내 버전, 최초 참여 시각, 기본 정보 JSON, 최소 계정 식별자 암호문 |
| `RawEvents` | 행동 한 건당 한 행. 식별·시각·맥락·버전·action·scope·payload JSON |
| `SurveyResponses` | 제출 한 건당 한 행. 가명 코드, 서버 수신 시각, 문항 버전, `{문항ID: 1~6}` 원응답 |

기본 정보는 시트의 저장 응답을 받은 후에만 가입 완료로 처리한다. 실패하면 입력 폼을 유지해 재시도하며, 자동으로 행동 수집을 켜지 않는다. 최초 참여자 등록은 멱등적이다. 검사 제출은 먼저 IndexedDB에 저장하고 재전송하며, 같은 제출 ID는 한 번만 누적한다. 문항별 응답 변경 이력은 `RawEvents`의 `survey_answer`, 최종 제출 원응답은 `SurveyResponses`에 따로 남는다. 기본정보는 `background-12-v1`, 검사는 제공받은 17문항·6점 척도 `ann-confidence-17-v1`이다. 심리측정 타당성을 자동 보장하거나 채점하지 않는다.

`Participants`에는 원 이메일·이름을 저장하지 않는다. 그래도 암호문과 기본 정보는 보호할 연구 자료다. 시트/Apps Script 공유 대상을 연구 책임자로 제한한다. Google Sheets의 숨김 탭·보호 범위는 열람 권한 분리가 아니므로 분석자에게 원본 문서 전체를 공유하지 말고, 필요한 가명 행동 자료만 별도 추출한다.

## 가명 처리와 로그인

- 공식 라이브러리가 Google ID 토큰의 서명·수신자(aud)·발급자·만료를 검증한다. 서버가 발급한 nonce도 일치해야 한다.
- `participantId = p_ + HMAC-SHA256(가명 전용 비밀키, [studyId, issuer, sub])`.
- `sub`는 Google 계정의 고유 식별자이며 이메일이 아니다. 연구별로 다른 가명 코드가 된다. **가명화이지 완전 익명화가 아니다.**
- 같은 `sub`, `studyId`, 가명 전용 비밀키이면 로그아웃·재로그인·다른 기기에서도 같은 ID가 계산된다. ID 생성 자체에는 DB 조회가 필요 없다. 첫 참여 여부·기본 정보는 시트의 `Participants`에서 조회하므로 영속 저장이 없는 것은 아니다. 이 세 값 중 하나가 바뀌면 다른 ID이며, 키를 잃으면 기존 ID 연결을 복원할 수 없다. 개발 모드는 별도 지정 키가 없으면 서버 시작마다 임시 키가 바뀐다.
- 최소 연결 정보 `{issuer, sub}`는 별도 32바이트 키로 AES-256-GCM 암호화한다. 매번 새 IV, studyId를 AAD로 사용한다. 복호화 키는 시트에 넣지 않는다. 계정 연결표가 필요 없다면 이후 연구 프로토콜에 맞춰 암호문 보관 자체를 제거할 수 있다.
- 이메일·이름·ID 토큰·비밀번호를 시트, 브라우저 localStorage, 행동 payload에 넣지 않는다. 세션 쿠키는 서명+HttpOnly+SameSite=Strict, HTTPS에서는 Secure. 브라우저가 전송하는 가명 ID를 서버의 권위 있는 참여자 ID로 신뢰하지 않는다.
- 상태 변경 요청은 정확한 Origin과 CSRF 토큰을 검사한다. 서버는 개인정보가 포함될 수 있는 예외 원문을 응답하거나 기록하지 않는다.
- 연구 참여 코드, 확정된 참여 안내 버전·프로필 승인 설정이 없으면 실수집 모드가 시작되지 않는다. 앱의 체크박스는 기관 연구 승인/보호자 동의/설명 절차를 대신하지 않는다. 배포 전 별도 검토 필요.

## raw 이벤트 사전

### 클릭·드래그 원시 기록 (`scope=interaction`)

- `ui_click`: 클릭한 **원래 페이지**와 요소 ID. 다음 페이지로 이동하기 전에 capture 단계에서 기록.
- `ui_pointer_start / ui_pointer_move / ui_pointer_end`: `gestureId`로 묶인 조작, 포인터 종류, 지속 시간, 종료/취소, 포인터 이벤트 수.
- `ui_input / ui_change`: 슬라이더와 숫자 입력의 이전·현재 값, 선택 목록의 항목 번호, 체크 상태. 키보드로 슬라이더를 바꿔도 기록. 연속 `input`과 조작 완료 `change`는 서로 다른 이벤트로 모두 남기므로 마지막 값이 같아도 분석에서 구분한다. 숫자 입력을 비우거나 유효하지 않은 입력은 `empty`/`valid`로 남기고 0으로 바꾸지 않는다.
- `elementId`: 코드의 ID 또는 data 속성과 구조상 순번. 버튼 문구·사용자가 정한 클래스 이름·URL은 기록하지 않는다. `app_build`와 소스 코드를 보존해 같은 버전의 요소를 식별한다.
- `positionX / positionY`: 허용된 그래프/슬라이더 요소 안의 상대 위치(0~1, 바깥으로 나가면 범위 밖 값). **모델 좌표가 아니며**, 모델 좌표는 별도 `prediction`/`parameter_change` 이벤트와 구분한다. 기존 100ms 시간 샘플링을 제거했고 브라우저가 전달한 달라진 좌표를 모두 기록한다. 좌표가 같은 연속 pointermove는 생략한다. 시작·종료는 별도 기록하며 브라우저/OS가 합쳐서 전달하지 않은 하드웨어 이벤트까지 복원하지는 못한다.
- 그리기 캔버스는 시작·종료·시간만 기록하고 획 좌표를 보내지 않는다(`coordinatesOmitted=true`). 입력 문장·이름·파일명·사진·인증 폼 내용은 제외한다. **숫자 자료의 원 수치는 기록**하며, 텍스트는 문장 대신 추출된 수치 특징만 남긴다. 전화번호 등 개인정보를 숫자 자료에 넣지 않도록 참여 안내에 명시했다. 기본 정보와 검사 원응답은 별도 버전형 저장 경로를 사용한다.
- 이 원시 UI 층과 의미 있는 명령 층은 **같은 행동을 서로 다른 관점으로 기록**한다. 둘을 합산해 클릭 횟수·참여도를 계산하지 않는다. `scope=interaction`도 이해도나 의도에 대한 판정이 아니다.

기록 예: `page=3`, `elementId=imageHidden`, `action=ui_input`, `previous=1`, `value=2`. 실제 페이지/요소는 조작 시점에 결정된다.

모든 행: `event_id`, `study_id`, 서버가 확정한 `participant_id`, `client_session_id`, `sequence`, `occurred_at_client`, `received_at_server`, `elapsed_ms`, `schema_version`, `app_build`, `condition`, `task`, `page`, `engine`, `workspace_id`, `dataset_version`, `model_version`, `action`, `scope`, `payload_json`.

빌드 전 `RESEARCH_BUILD_ID`를 Git 커밋/실험 버전 코드로 설정하면 해당 클라이언트 번들의 버전이 각 이벤트에 남는다. 기본은 `development`이며 실제 연구에서는 반드시 명시한다. `sampleToken`은 현재 모델 작업 공간에서 동일 입력을 다시 확인했는지 연결하는 임시 무작위 ID다. 픽셀의 공개 해시가 아니고, 입력 대조표는 기기 메모리에만 남는다(최대 1,000개, 새 탭/작업 공간에서는 새 ID). 전송하지 않은 그림을 재구성할 수 있는 값은 아니다.

- `sequence`는 같은 탭의 수집 세션 내 순서. 재접속·중복·멀티탭 구분에 session ID와 함께 사용한다. 서버 도착 순서는 행동 순서가 아닐 수 있다. 클라이언트 시계는 오차가 있을 수 있다.
- `workspace_id`는 해당 모델 인스턴스 식별자. 초기화·모델 변경 시 modelVersion 증가, 자료 구조 변경 시 datasetVersion 증가. 이해의 실험 모델은 연습 모델과 다른 engine/workspace다.
- condition은 실제 사용한 화면(`experimental`/`comparison`)이다. 무작위 배정값이 아니다. 현재는 학생이 둘 다 열 수 있다. 배정·순서 통제는 연구 설계에서 정해야 한다.
- 클래스 이름·자료 이름은 자유입력이므로 수집하지 않는다. `label`은 해당 datasetVersion에서 0부터 시작하는 클래스 번호다. 클래스 삭제 시 번호가 재배치될 수 있다.
- 값은 화면의 소수 두 자리 표시가 아니라 **계산에 사용한 수치 그대로** 보존한다.

`src/research/schema.ts`가 허용하는 숫자·boolean·코드 토큰만 받아들이며, 서버도 동일하게 검사한다. 임의 영역 클릭, 키 입력 전체, 호버 전체, 화면 캡처를 수집하지 않는다. 선택되지 않은 문장 내용, webcam 매 프레임 원본은 수집하지 않는다. 앱이 처리한 변경 입력의 예상 로그는 시간으로 생략하지 않는다. 자동 학습도 **실제로 화면을 갱신하는 배치 완료마다** 횟수·오차·정답률을 남기며, 배치 내부의 모든 곱셈/가중치 행렬/화면에 표시하지 않은 각 epoch 중간값까지 저장하는 것은 아니다. 어떤 기록이 빠졌는지는 `collection_error`도 확인한다. 완전한 화면 영상 재생이나 원본 이미지 재학습용 데이터베이스가 아니다.

### 권장 분석 단위

원 행을 수정하지 말고 별도 분석 사본에서 `(participant, condition, task, workspace, session, sequence)`를 이용해 `자료 수정 → 학습 → 테스트 → 설정 수정 → 재학습 → 재테스트` 전환을 재구성한다. 단일 클릭만으로 ‘오류 인식’, ‘의도적인 개선’, ‘심층 이해’라고 코딩하지 않는다. 정답률은 **학습 정확도**와 **학습에 넣지 않은 검사 정확도**를 분리한다. 머무른 시간이나 조작 수가 곧 학습 성과라는 가정을 하지 않는다. 공통 외부 검사/관찰과 함께 해석한다.

## 비교형의 동일점과 차이

학생 조작 수준을 Teachable Machine의 핵심 이미지 분류 흐름에 맞췄다. 실제 Google 제품 복제, MobileNet 전이학습, 소리/포즈/기기 확장과 동등하다고 주장하지 않는다.

- 같은 `ImageLabStore`와 `pixelNetwork` 수학 코드를 이용한다. 티처블 머신은 196픽셀·은닉 16개·tanh, 300회·0.12, full-batch다. 학생은 학습/중지만 조작하고 학습 횟수·학습률·뉴런 수는 변경하지 않는다.
- 숫자/OMR 예시도 기존 앱의 동일 생성기를 사용한다. 학습용과 분리한 합성 holdout 검사로 최소 성능을 회귀 검증한다. 이 결과를 실제 학생 손글씨·다양한 배경의 웹캠 일반화 성능으로 제시하지 않는다.
- 기존 탐구형의 map 모드는 고른 두 특징에 제한하고 은닉 수를 직접 바꿀 수 있다. 비교형 pixels 모드와 **입력 정보량/설정까지 같은 실험은 아니다**. UI 효과만 비교하려면 과제·자료·학습시간·모델 모드·은닉 수·활성화·학습률을 연구자가 맞추고 기록으로 검증해야 한다.
- 웹캠은 작은 흑백 모델이므로 배경·거리·조명을 고정하고 클래스별 다양한 예시를 충분히 모은 파일럿이 필요하다. 실제 카메라 분류 성능은 아직 검증하지 않았다.
- 비교형 모델 내보내기에는 연구 ID·로그·사진·학습 자료를 포함하지 않는다. 클래스명은 사용자가 정한 모델 라벨이므로 파일에 포함된다.

## 실연결 설정 — 아직 실행하지 않음

1. 연구 기본 항목, 참여 안내/보관 기간/삭제 절차, 접근 권한, 검사 문항·시점·배정 방식을 확정한다. `schema.ts`의 profile 스키마와 UI 항목을 함께 수정하고 버전을 바꾼다. 설문은 `RESEARCH_INSTRUMENT_JSON`으로 주입한다.
2. Google Cloud OAuth 웹 클라이언트를 생성하고 실제 사용할 origin을 등록한다. Client ID만 브라우저에 공개한다. 일반 Google 로그인만 사용하며 학생에게 Sheets 접근 권한을 요청하지 않는다.
3. 연구자 계정으로 독립 Apps Script를 만들고 `integrations/google-apps-script/Code.gs`를 복사한다. Script Properties:
   - `SHEET_ID=1EO9SCthQHKgpCgiSVm8C571-LJwDqC-GE3JzSZxCrlU`
   - `STUDY_ID`: 서버 `RESEARCH_STUDY_ID`와 동일
   - `GATEWAY_SECRET`: 서버와 공유할 별도의 무작위 비밀키
4. 연구자로 실행하는 웹 앱 배포를 **추후 별도 승인 후** 수행한다. 서버 호출을 받을 수 있게 하되 요청은 HMAC 검증으로 보호된다. `/exec` URL을 서버에만 설정한다. 서명 유효기간 5분, ScriptLock으로 dedupe+append를 직렬화한다. 탭 헤더가 다르면 덮어쓰지 않고 거부한다. 원래 gid=0 시트는 건드리지 않고 위 이름의 새 탭을 만든다.
5. `.env.example`의 서버 값들을 별도로 생성·설정한다. session/pseudonym/identity/gateway는 **서로 다른 키**, 임의 생성 32바이트 이상. identity는 base64 32바이트. 실제 값은 Git·클라이언트 번들·시트에 넣지 않는다. 키 변경은 기존 가명 연결 및 암호문 복호화에 영향을 주므로 연구 중 무계획 교체 금지.
6. 승인된 profile과 동의 버전을 설정해야 `RESEARCH_MODE=google`이 열린다. 참여 코드 32자 이상. draft 검사 문항은 google 모드에서 제출 금지.
7. 스테이징에서 본인 테스트 계정으로 최초/재로그인, 잘못된 audience/만료/nonce, 참여 전 수집 금지, 실제 시트 도착·재전송 중복, 네트워크 단절 복구·로그아웃, 계정 변경, 반별 동시 접속 부하를 검증한다. 이후에만 학생에게 제공한다.

```json
{"version":"pilot-pre-v1","title":"활동 전 검사","draft":false,"anchors":["전혀 그렇지 않다","그렇지 않다","보통이다","그렇다","매우 그렇다"],"items":[{"id":"Q01","text":"확정된 문항으로 교체","required":true}]}
```

### 운영 한계

Apps Script는 소규모 파일럿 수신기다. 중복 확인 시 행 ID를 읽고 잠금을 사용하므로 데이터량이 늘면 느려진다. Google 실행시간/동시실행/쿼터 및 학교 계정 정책에 따라 실패할 수 있다. 실패한 전송은 기기에 남지만, 장기 수집·큰 동시접속에는 전용 DB/내구 큐를 먼저 받고 Sheets를 분석용 mirror로 만드는 구성이 필요하다. 현재 서버의 rate limiter는 프로세스 단위이며 분산 서버 전체 제한을 대체하지 않는다. 학생 브라우저의 수치는 신뢰된 시험 성적이나 부정행위 방지 증거가 아니며, 클라이언트 측 조작 가능성을 배제하지 않는다.

동시 수집을 위해 전송을 기기별로 분산하고, 최대 배치를 50→200건으로 늘리되 바이트 상한도 둔다. 수신기는 중복 확인에 전체 20열 대신 ID 3열만 읽는다. 잠금 대기는 서버 제한(15초)보다 짧은 1초로 바꾸어 경합 시 실패 응답 후 재시도하도록 했다. 저장 확인 전에는 대기 기록을 지우지 않는다. ID 읽기는 여전히 누적 행 수에 비례하며, 이 수정으로 Google 처리량을 보장하는 것은 아니다.

### 30명 동시 수집 검증 범위

`server/research/handler.test.ts`의 로컬 모의 시험:

- 서로 다른 30개 인증 세션·가명 코드·기본 정보 등록.
- 계정별 600건, 총 **18,000건**을 동시에 전송(200건 배치), 수치 정밀도·소유 계정 확인.
- 참가자별 첫 행동 배치와 검사 제출은 저장 후 응답 유실을 강제로 발생시킨 후 재전송. 모든 배치·검사에 중복 전송도 추가.
- 최종 **참여자 30건, 행동 18,000건, 검사 응답 30건**으로 중복 없이 확인. 수치/응답/가명 매핑 일치.
- Apps Script 코드는 별도 모의 SpreadsheetApp 시험으로 잠금 실패 시 무기록·무승인, 재전송 중복 제거, 200건 배치를 검증.

이 테스트는 Google 인증 검증기·저장 매체를 모의한 **코드 경로 시험**이다. Google 지연, 학교 Wi-Fi, 서버리스 제한, Google 쿼터를 재현한 실제 30대 성능 시험이 아니다. [공식 Apps Script 제한](https://developers.google.com/apps-script/guides/services/quotas)에 사용자당 동시 실행 30개가 명시되어 있다(2026-09-29 확인). 연구자로 실행하는 현재 수신기 설계에서는 이를 고려해야 하며, **동시 접속 30명 = 항상 동시에 스크립트 30개 실행**이라는 뜻도 아니다.

실수집 전에는 승인된 스테이징 수신기에 30대가 숫자 입력·슬라이더 조작·학습·설문 제출을 수행하고, 전송 대기함이 모두 비워진 뒤 계정별 event ID/세션 순번과 시트 행을 대조한다. 중간에 인터넷 끊김·재연결·새로고침·로그아웃/동일 계정 재로그인도 확인한다. 장시간 누적 자료가 있는 시트에서 최대 지연/실패/중복/누락을 별도로 확인해야 한다. 현재 **실 시트 시험·배포·실데이터 전송은 하지 않았다.**

기록 완료 후 응답 손실은 event ID로 중복을 막는다. UUID 충돌·관리자의 시트 편집/행 삭제·장애·쿼터를 모두 포함한 절대적 exactly-once/무손실을 보장하지 않는다. 시트는 숫자·문자열 원값을 저장하고 수식으로 시작하는 문자열은 무해화한다.

## 자료 → 좌표 애니메이션 (2026-09-30, 로컬 개발)

이해 → 자료 비교에서 특징을 선택하면 고른 실제 자료 한 개의 해당 영역·합·좌표 계산이 자동 재생된다. 같은 사례의 가로/세로 계산은 나란히 표시한다. 원본 그림은 유지하고 계산된 좌표값만 이동시킨 뒤 나머지 자료를 놓는다. 특징 하나를 바꾸면 바꾼 축으로만 이동한다. 애니메이션 중간 좌표는 UI 전용이며 학습 자료·모델에는 기록하지 않는다. 도착 좌표는 연습에서도 쓰는 `ExplorationSource` 값이다.

- `visualization_change`: `projection-start/pause/resume/skip/complete/cancel/dimension` 사건과 축·완료 여부.
- `projection-example`: 대표 자료가 바뀔 때만 행 번호(`sampleId`), 실제 도착 `coordinates`, 계산에 사용한 `values` 기록. 이미지의 values 순서는 `[특징 합, 전체 평균, 공통 크기]`, 숫자·텍스트는 `[원값, 최솟값, 최댓값]`, 승부차기는 `[방향 좌표]`. 그림 원본·텍스트 원문은 보내지 않는다.
- 정답 클래스는 설명할 대표 자료 선택과 색에만 쓰고, 좌표 계산에는 쓰지 않는다.
- 움직임 줄이기 설정에서는 최종 좌표를 즉시 표시한다. 화면 이탈 시 이전 재생을 취소한다. 재생 중에는 다른 특징을 선택할 수 없고, 일시정지·결과 보기 버튼은 사용할 수 있다. **애니메이션 프레임별/시간 간격별 이벤트는 생성하지 않는다.**

추가 테스트: 한 축 변경 시 반대 축 불변, 대표 자료/나머지 도착 좌표, 정지·재개·건너뛰기·재생 취소·움직임 줄이기, 원자료·모델 불변, 대표 한 개 재생의 유한한 사건 로그. 실 Google 인증/시트 연결·배포는 이 변경에서도 수행하지 않았다.

## 읽기 전용 학습 흐름과 연결값 탐구 (2026-10-01, 로컬 개발)

- 연습 화면의 이동 흔적 도구 모음을 제거했다. 실제 뉴런 기준선과 최종 경계는 유지한다.
- 이해의 마지막 장면에서 ×0과 ×1을 비교한다. 선택한 뉴런→선택한 클래스의 연결 하나만 변경하고 실제 뉴런 값·기여한 점수·지도 경계가 함께 바뀐다. 양수 신호가 있는 실제 자료가 있으면 그 사례로 이동하며, 가상의 수치를 만들지 않는다. 이 곱할 수는 정답 번호가 아니며 중간값과 음수도 가능하다. `parameter_change/connection-example`에 전후 값·뉴런·출력·좌표를 기록한다.
- 티처블 머신: 자료 / 학습 과정 / 새 자료로 확인 탭. 학습 중 자료 분포·각 은닉 뉴런의 반응·각 자료의 실제 예상을 갱신한다. epoch·학습률·은닉 수 조절기는 노출하지 않는다. 학습은 위에 기록한 자동 설정을 이용한다.
- 자료 분포는 정답을 사용하지 않는 그림 요약이며 학습 중 고정된다. 모델은 원본 196개 입력으로 계산한다. 뉴런별 색 지도와 최종 경계는 평균 그림을 지나는 같은 2차원 단면의 실제 계산값이다. 단면의 각 좌표에서 전체 모델과 일치하는지 자동 검증한다. 실제 자료 점을 이 단면 배경에 겹쳐서 정확도를 주장하지 않는다. 선택한 자료의 수치와 예상은 원본 전체 계산이다.
- `page_view/open-teachable`에 `traceVersion=tm-live-flow-v2`, 점 선택에는 `sample_select/flow-map`, 뉴런 관찰에는 `visualization_change/flow-neuron`을 기록한다. 화면 갱신 자체로 추가 행동 이벤트를 만들지 않는다.
- **연구 조건 변경:** 이 버전에는 내부 시각화가 있다. 이전의 ‘내부 시각화가 없는 비교형’과 같은 조건으로 합쳐 분석하면 안 된다. 이해 단계·직접 가중치 조작은 없지만, 읽기 전용 내부 관찰이 가능하므로 노출 차이를 구분해야 한다.

1397×655 노트북과 768×1024 태블릿에서 연결값 장면 및 티처블 머신 학습 패널의 표시와 높이를 확인했다. Google 실제 인증·시트 부하 시험은 이 UI 검증에 포함되지 않으며, 배포·원격 푸시·실 시트 쓰기는 수행하지 않았다.

### 조작 흐름과 표시 변경

- 자료 다음에는 가로 특징 선택 → 대표 그림 3장과 나머지 자료의 가로 배치 → 세로 특징 선택 → 세로 이동으로 이어진다. 원본 및 학습 좌표를 변경하는 애니메이션이 아니다.
- 그림 특징 만들기 도구 대신 오른쪽−왼쪽, 위−아래, 전체 진하기, 가운데 진하기, 열 번호×진하기 합을 제시한다. 모든 웹캠 과제에서 잘 구분된다고 보장하지 않으며 배경·위치 변화의 영향도 확인해야 한다.
- 뉴런 조절과 개선 장면은 각기 세 입력 연결값을 실제로 변경해야 다음으로 진행한다. 정해진 정답 방향을 강제하지 않으며 이전 장면은 다시 볼 수 있다.
- 이해 단계의 피드백은 선택한 자료 한 개의 실제 클래스별 예상 확률이다. 출발점 모델과 현재 모델을 같은 좌표에서 비교한다. 정답과 가장 강한 다른 후보를 기본으로, 전체 클래스 확률은 펼쳐서 확인한다. 전체 정답률·점과 선의 거리가 아니다. 기존 기하평균 점수는 이해 화면에서 제거했다. raw 로그의 손실·확률·가중치는 변환하지 않는다.
- 이해의 ‘모델과 비교’는 같은 대표 자료 한 개, 같은 출발점, 선택한 수 하나에 대해 실제 교차엔트로피 기울기로 갱신한다. 연습의 전체 데이터 학습과 구분한다. 특징 애니메이션 중에는 특징/자료 선택을 잠그며 완료·건너뛰기·이탈 시 해제한다. 좌표는 실제 특징의 합 → 전체 평균 빼기 → 공통 간격으로 나누기이며, 이미지 압축 연출은 사용하지 않는다.
- 새 연습 모델은 1회씩 10회 → 100회 → 계속 학습 순서로 열린다. 모델 초기화 때 다시 시작한다. 비교형의 자동 설정은 변경하지 않는다.
- 선택 클래스의 모든 자료를 페이지로 볼 수 있으며, 그림 선택 후 X로 한 장을 삭제한다. 삭제된 수, 자료 버전과 선택 이벤트를 원래 수집 체계로 기록한다.
- 연습의 두 특징 입력은 가로·세로 원 두 개, 그림 전체 입력은 196칸 묶음으로 구분한다. 기존 선의 점선은 활성 이해/연습 지도에서 제거하고 원형 점 표시를 통일한다.
